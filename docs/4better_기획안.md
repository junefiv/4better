# 4better 기획안

비공개 친구 리그에서 같은 목표를 매주 반복하고, 서로의 기록으로 확인하는 목표 리그 앱

문서 기준: 2026년 9월, V1 코어 MVP 및 이후 홈·목표 프리셋 반영분

버전 순서와 스프린트는 [`개발_계획.md`](개발_계획.md), 지금 위치는 [`개발_현황.md`](개발_현황.md)다.

---

## 1. 한 줄 설명

4better는 2~4명의 친구가 **같은 주간 목표**에 함께 들어가, 기록을 제출하고, **본인을 제외한 전원이 확인**한 뒤에야 실적이 확정되는 비공개 목표 리그 앱입니다.

혼자 쓰는 습관 트래커가 아니라, **작은 방에서 서로를 증인으로 두는 구조**입니다. 매주 라운드가 바뀌고, 끝난 리그도 남습니다. 실제 돈의 수납·보관·송금은 하지 않으며, 페널티와 보상은 **규칙을 이해하기 위한 예상 정산**만 보여 줍니다.

---

## 2. 서비스 설명문

친구들과 “이번 주는 공부 10시간”, “글쓰기 5회” 같은 약속을 해도, 혼자 앱에 체크하면 쉽게 흐려집니다. 4better는 그 약속을 **리그(방)** 로 만듭니다.

방을 만든 사람이 목표 종류와 주간 목표량, 기간을 정합니다. 초대받은 사람은 규칙을 읽고 동의한 뒤에만 시작합니다. 한 주(1라운드) 동안 각자 기록을 남기고, 친구들이 그 기록을 승인하거나 설명을 요청합니다. 본인 제외 전원이 인정해야 그 주의 실적이 확정됩니다.

홈에서는 내가 속한 방만 카드로 봅니다. 카드에는 목표 종류 뱃지, 방 이름, 이번 라운드 참여자별 기록이 있고, 표를 좌우로 밀면 이전 라운드도 같은 카드 안에서 볼 수 있습니다. 집중 시작, 기록 확인, 승인은 카드를 눌러 방 안으로 들어갔을 때 합니다.

과정은 사진 한 장과 2초 영상으로 남길 수 있습니다. 이 리캡은 방 멤버에게만 보이는 비공개 기록입니다.

4better는 “더 많은 사람 앞에서 인증하는 소셜 챌린지”가 아닙니다. **아는 사람 몇 명과, 같은 규칙으로, 매주 한 번 더 반복할 수 있는가**를 검증하는 제품입니다.

---

## 3. 해결하려는 문제

| 기존 방식의 한계 | 4better의 대응 |
|---|---|
| 혼자 체크하면 중간에 포기해도 아무도 모름 | 2~4명이 같은 규칙에 동의하고 서로의 기록을 봄 |
| 공개 SNS 챌린지는 부담이 크고 관계가 얕음 | 초대된 친구만 들어가는 비공개 방 |
| “했다”는 말만으로 끝나기 쉬움 | 본인 제외 전원 확인 후에만 실적 확정 |
| 주가 바뀌면 지난주가 사라짐 | 라운드 단위로 기록하고, 홈 카드에서 이전 라운드를 다시 봄 |
| 습관 앱의 목표가 너무 자유로워 비교가 어려움 | 앱이 주는 목표 프리셋만 사용 |

검증 가설은 다음과 같습니다.

> 친구 2~4명이 같은 목표와 규칙에 동의하고, 기록을 제출하고, 본인을 제외한 전원의 확인을 받아 주간 결과를 확정한 뒤, 다음 주에도 반복하는가?

가장 이탈하기 쉬운 지점은 **시작 전 전원 동의**, **제출 후 전원 확인**, **마지막 주 연장 합의**입니다. 제품은 이 세 지점을 상태와 짧은 문구로 분명히 보여 줍니다.

---

## 4. 누구를 위한 제품인가

- 이미 친한 2~4명과 짧게 같이 하고 싶은 사람
- 공개 랭킹이나 불특정 다수 인증은 부담스러운 사람
- 공부, 운동, 창작, 수면처럼 **한 주에 반복할 수 있는 목표**를 가진 사람

첫 사용은 Google 로그인 또는 미리보기 계정으로 시작합니다. 닉네임은 2~20자입니다.

---

## 5. 핵심 반복 구조

```
초대 → 규칙 동의 → 라운드 진행 → 기록 제출 → 친구 확인 → 주간 확정 → (다음 라운드 또는 연장/종료)
```

1. 방장이 리그를 만들고 목표 프리셋, 주간 목표량, 기간을 정합니다.
2. 초대 코드 또는 `fourbetter://invite/...` 링크로 친구가 들어옵니다.
3. 전원 규칙에 동의하면 방이 시작됩니다.
4. 1주 = 1라운드입니다. 멤버는 타이머·횟수 기록과 설명을 남깁니다.
5. 다른 멤버가 승인, 설명 요청, 미인정을 합니다.
6. 본인 제외 전원이 승인하면 그 기록은 확정되어 라운드 실적에 들어갑니다.
7. 주가 끝나면 순위와 예상 정산을 보고, 마지막 주면 연장 여부를 묻습니다.

## 6. 목표 프리셋

사용자는 목표를 직접 만들지 않습니다. 앱이 제공하는 종류만 고릅니다.

| 프리셋 | 측정 | 주간 목표 단위 |
|---|---|---|
| 독서 | 횟수 | 회 |
| 글쓰기 | 횟수 | 회 |
| 그림 | 횟수 | 회 |
| 장소 방문 | 횟수 | 회 |
| 자전거 | 시간 | 시간(내부는 분) |
| 러닝 | 시간 | 시간 |
| 워킹 | 시간 | 시간 |
| 등산 | 시간 | 시간 |
| 헬스 | 시간 | 시간 |
| 공부 | 시간 | 시간 |
| 수면 | 시간 | 시간 |

시간형 목표는 집중 타이머로 쌓고, 횟수형 목표는 제출 횟수로 쌓습니다. 홈 카드 제목 앞에는 이 프리셋이 뱃지로 붙습니다.

## 7. 현재 화면과 정보 구조

### 7.1 홈

- 인사, **진행중 / 종료된** 토글, 리그 카드. 진행 중 카드 안에 그 방의 **퀵 스타트** 버튼이 있음
- **진행중 / 종료된** 토글
- 가운데 **동그라미 +** 로 새 리그 생성
- 내가 속한 리그 카드만 표시

카드에 있는 것:

- 목표 뱃지 + 방 이름
- 오른쪽 끝 라운드 표시 (`라운드 3/4`)
- **내** 라운드 기록 · 달성률. 좌우로 밀면 이전·다음 라운드
- 진행 중이면 퀵 스타트 버튼

카드에서 하지 않는 것:

- 다른 멤버 진행, 다른 사람 기록 승인, 주간 리캡 갤러리

다른 사람 기록은 카드를 눌러 방 안으로 들어갔을 때 봅니다.

### 7.2 방 안

- 규칙 동의, 초대, 시작 대기
- **라운드 진행**: 세션마다 다른 UI. 홈 카드는 내 기록만, 방 안은 전원. 좌우로 라운드 이동
- 집중 타이머(앱을 닫아도 시작 시각 기준으로 이어짐)
- 기록 제출, 설명, 사진·2초 영상
- 친구 기록 확인(승인 / 설명 요청 / 미인정)
- 주간 결과와 예상 정산
- 마지막 주 연장 동의

### 7.3 공통 이동

플로팅 메뉴: 홈, 확인, 리캡, 설정. 새 리그 만들기는 메뉴가 아니라 홈의 + 버튼입니다.

### 7.4 설정·안전·운영

- 푸시 알림 동의
- 신고, 차단, 탈퇴
- 관리자: 사용자·리그·교착·업로드 실패·제한·감사 로그(내부 QA·운영용)

## 8. 규칙과 정산 원칙

- 인원: 2~4명
- 기록 인정: **본인 제외 전원 확인**
- 수정 제출: 새 버전이 생기고, 이전 승인은 이어받지 않음
- 동점: 공동 순위 비율을 합친 뒤 균등 분배
- 예상 페널티 풀: 목표 미달 인원 × 주간 페널티
- 플랫폼 계산 수수료: 풀의 1%(표시용)
- 기본 순위 분배 예시: 45 · 30 · 20 · 5%

**앱이 돈을 받거나, 보관하거나, 보내지 않습니다.** 금액은 규칙을 같이 이해하기 위한 예상치입니다. 실제 정산이 필요하면 멤버가 방 밖에서 합니다.

---

## 9. 의도적으로 하지 않는 것

- 불특정 다수 공개 챌린지, 팔로워 피드
- GPS, Health Connect, HealthKit 등 센서 자동 기록
- 광고, 구독, 포인트
- 실제 결제·에스크로·송금
- 고객(최종 사용자)에게 MCP나 개발자 권한을 주는 일

모바일 앱은 클라이언트가 계산한 달성·정산을 최종 진실로 쓰지 않습니다. 서버에 붙는 구간에서는 서버 트랜잭션으로 확정하는 것이 원칙입니다.

## 10. 기술 개요

| 구분 | 내용 |
|---|---|
| 클라이언트 | Expo, React Native, TypeScript, React Native Paper |
| 플랫폼 | Android, iOS, Web |
| 백엔드 | Supabase(Auth, Postgres, RLS). 프로젝트 `iaslvwciprbtcrcoafoi` |

## 11. 현재 구현과 남은 일

자세한 체크리스트는 [`개발_현황.md`](개발_현황.md)를 본다. 요약만 적는다.

이미 있는 것:

- Google 로그인·닉네임
- 로그인 후 리그 생성, 내 리그 조회, 원격 타이머·체크 저장
- 홈 리그 카드, 진행중/종료 토글, 라운드 스와이프
- 목표 프리셋 UI (베타 검증 범위는 공부·글/그림)
- 확인·리캡·예상 정산·프로필 화면 (로컬/미리보기 포함)

아직 서버로 닫히지 않은 것:

- 초대 참가, 전원 규칙 동의 후 시작
- 본인 제외 전원 승인·실적 확정
- 주간 순위·분배의 서버 계산
- Storage 리캡 업로드, 푸시, 연장 합의

외부 설정:

- 스토어용 푸시(APNs/FCM), EAS 프로젝트
- Supabase Storage 비공개 미디어와 서명 URL
- 알림 작업 처리(Edge Function 등)
- 관리자 권한의 서버 측 부여
- 탈퇴와 법적 보존 정책

## 12. 성공을 보는 방법

숫자보다 먼저 아래가 통하는지를 봅니다.

- 전원 동의가 필요한 이유를, 긴 설명 없이 이해하는가
- 확정 실적과 확인 대기 실적을 구분하는가
- “3명 중 2명 확인”이 본인을 뺀 친구들 이야기임을 아는가
- 설명 요청을 거절과 다르게 받아들이는가
- 1%와 페널티 금액이 **실제 결제가 아님**을 오해하지 않는가
- 마지막 주 무응답이 연장을 동의한 것이 아님을 아는가
- 홈에서 내 방과 라운드 위치를 바로 찾는가

이 이해가 확인된 뒤에 실제 회원 데이터, 서버 타이머 복구, 미디어 업로드를 더 단단히 붙입니다.
